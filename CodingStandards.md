The StockBuddy project follows basic coding standards to keep the code readable, consistent, and easy for all team members to understand.

Naming Conventions: Classes and methods use PascalCase (e.g., CheckoutService, AddProduct). Variables and parameters use camelCase (e.g., totalPrice, barcode).

Code Organization: Each class is placed in its own file and files are named after the class they contain. UI code (WinForms) is kept separate from database and business logic when possible.

Formatting: Code is properly indented using 4 spaces and consistent spacing is maintained for readability.

Comments: Comments are added where necessary to explain important logic or complex sections of code.

Database Queries: All database queries use parameterized SQL commands to prevent errors and improve security.

Error Handling: Input validation and error messages are used to prevent crashes and guide the user when invalid data is entered.

These standards help ensure the codebase remains maintainable and easy to work with throughout the development process.
