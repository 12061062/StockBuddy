StockBuddy implements password security by storing hashed passwords instead of storing plain text passwords in the database. This means that when a user creates or enters a password, the original password is never saved directly. Instead, the application runs the password through a hashing function and stores the resulting hash value. When the user logs in later, the entered password is hashed again and compared to the stored hash.

To strengthen security, password hashing should be performed with a salt. A salt is a random value generated for each password and stored alongside the hash. This ensures that even if two users choose the same password, their stored hashes will still be different. Using a salt also helps protect against common attacks such as rainbow table lookups.

In StockBuddy, hashing is used to protect user credentials for local authentication roles such as cashier and manager. During login, the application verifies the password by hashing the entered value with the stored salt and comparing the result to the saved hash. This approach improves security by preventing passwords from being exposed directly in the database and follows standard best practices for credential storage.

For implementation, a secure algorithm such as PBKDF2 should be used because it is specifically designed for password hashing and includes repeated iterations to make brute-force attacks more difficult. Overall, hashing provides an essential layer of protection for user accounts and helps ensure that authentication data is handled more securely within the system.
